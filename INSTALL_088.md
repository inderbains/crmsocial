# RealVolt Fix 088 — Platform management foundation (no Stripe)
Requires the working Fix 084–086 SQL, platform admin email Edge Function and admin CSS. Based on Fix 086, not Fix 087; Stripe is deliberately omitted. Back up and use a staging project first. No change to agent or brokerage workspace files.

1. Supabase SQL Editor: open `supabase/088_platform_management.sql` and copy its entire contents, not the filename. Run once. It creates private plan, assignment and deletion-review tables and owner-verified RPCs.
2. Supabase Edge Functions: deploy a new function `platform-account-control` via editor, using the entire `supabase/functions/platform-account-control/index.ts`. The function verifies the Auth token, the platform owner and the email verification RPC itself. Keep existing secrets and functions. It uses the built-in Supabase URL, anon and service-role keys server-side; do not expose the service-role key. No Stripe key is required.
3. GitHub: replace `app/admin/page.tsx` and add `app/admin/management-panel.tsx`, `app/admin/management.module.css`. Keep `platform.module.css`. Run `npm run build` in current repo, then deploy. Do not replace unrelated files.
4. Visit `/admin/`, sign in and verify by email. Search the directory to locate an account, then select it in Plans & account controls. Plan assignment for a brokerage member affects the entire brokerage plan configuration, not an individual seat. Registered membership count is not a billable seat count. Initial plans are CAD 49.99/month and 69.99/agent/month; editable. Zero-price custom plans are possible. Future modules are metadata only.
5. Test on staging: create/edit a plan, assign to an independent account and brokerage, reject wrong plan type; try RPCs with unverified/non-owner users and confirm denial; test sign-in ban/removal on a disposable agent, and confirm protected owner cannot be targeted. Check existing JWTs separately: sign-in ban does NOT guarantee immediate session revocation. Request/cancel deletion review; verify records remain. Check audit entries, refresh/back/sign-out from Fix 086, and separate agent login.

## What is not implemented
No actual subscription billing, payment collection, revenue reporting, access enforcement by plan, full account suspension, forced logout, permanent account deletion, trial/discount scheduling, live online tracking or password reset. Deletion review is a stored request, not a deletion. Sign-in ban only blocks new authentication; existing sessions and API access need separate controls. Removing a ban does not override other access restrictions. No claims of live verification; static source checks and syntax only. The current live repository and database were not accessible. Stripe and automatic payment recovery are deferred. Independent agent classification here means no brokerage membership; standalone onboarding may need separate work.
