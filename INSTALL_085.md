# RealVolt Fix 085 — Email code for platform owner

Requires Fix 084. Replaces authenticator-app verification ONLY for /admin/. It is a custom email step-up check, not Supabase AAL2 MFA. Password and owner allowlist remain required. Normal workspace and invitation security remain untouched. Email is weaker than TOTP if the inbox is compromised. Keep the owner's inbox secured with its own MFA. Never expose a setup key or OTP in screenshots.

## Install on staging first
1. Back up current source and database. Open the complete `supabase/085_platform_email_verification.sql` in a text editor, copy its contents into Supabase SQL Editor, and run. Do not paste only the filename. This replaces the overview RPC's AAL2 requirement with a server-side email verification check tied to a live password-authenticated session. Old admin frontend will no longer work after this migration until the remaining files are deployed. Plan a short maintenance window. Existing account/data records are not deleted.
2. Deploy the new `supabase/functions/platform-admin-email/index.ts` as a Supabase Edge Function called `platform-admin-email`, using the browser editor or `supabase functions deploy platform-admin-email` from the correct linked project. The function verifies the user JWT through Auth and checks the owner/session through the database. Do not disable auth checks in code. It requires standard Supabase function env vars SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY and SUPABASE_ANON_KEY.
3. In Edge Function Secrets, reuse the existing working invitation provider: INVITATION_EMAIL_PROVIDER=gmail with GMAIL_SMTP_USER and GMAIL_APP_PASSWORD, or resend with RESEND_API_KEY and verified CLOSING_FROM_EMAIL. Optional PLATFORM_EMAIL_PROVIDER overrides the invitation provider for this function only. Do not paste secrets into GitHub or share them here. If the provider does not send, do not bypass verification. Gmail SMTP support must be tested on your deployed runtime; Resend needs a verified sender.
4. Replace ONLY `app/admin/page.tsx` in GitHub. Keep the existing `app/admin/platform.module.css` from Fix 084. Run the normal production build and deploy. Open /admin/ and log in as the configured owner. Check the owner inbox and enter the six-digit code. Resend after at least 60 seconds if needed; at most five issues per hour. A failed provider send consumes a request. Codes expire in 10 minutes, allow five wrong attempts, and are single-use. Verified access expires after one hour and is bound to that Supabase session. A reload requires a new login because the admin browser session is memory-only.
5. The old authenticator setup key was exposed. Remove the exposed enrollment using Supabase's authorized MFA factor management; do not use it. This migration intentionally does not delete MFA factors globally or modify existing workspace authentication. If you have a verified TOTP factor and other features depend on AAL2, keep their independent MFA requirements intact.

## Mandatory staging tests
- Non-owner and anonymous requests to email issuance, verification, and overview must fail, including direct API calls. Authenticated users cannot directly call the service-only issue RPC or read the private challenge table.
- Owner password login alone cannot access the overview, even with an old AAL2 token; a valid email code is required. Test wrong/expired/reused code, five-attempt lockout, resend delay and hourly cap.
- Verify a code issued to session A cannot activate session B; a revoked session cannot access the overview; verify after one hour requires fresh email verification. Check that the code always goes to the registered verified owner, not a supplied destination.
- Confirm normal brokerage sign-in, invitations, data isolation and existing Fix 083 permissions are unchanged. Check mail provider delivery and logs without exposing codes.

## Limitations and rollback
Only source checks and syntax transpilation were performed. No live Supabase migration, database integration test, email send or full Next build was performed. No verified delivery or security certification is implied. Fix 084's overview function remains otherwise identical; new admin powers are not added. For rollback restore the original Fix 084 SQL and page (TOTP required again), revoke/delete the new Edge Function, and remove the unused email challenges/functions only after checking dependencies. Do not restore the exposed authenticator factor.
